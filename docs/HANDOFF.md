# Handoff: build pipeline bring-up (Android + WebGL)

Status as of 2026-11-20. Written for an engineer or AI agent picking this project up cold. Read this first, then
`README.md` (which has the day-to-day build commands and the earlier "Setup Notes").

## 1. Where things stand

- `sample-game/` is a Unity 6 (6000.6.9f1) URP project that consumes 29 local UPM packages from
  `packages/com.nimbus.*` (116 asmdefs, 136 `.cs` files).
- On 2026-11-19 local builds succeeded for **Android** (APK) and **WebGL**. Both artifacts are still on disk under
  `sample-game/Builds/` (gitignored).

- The only scene is the empty URP template `SampleScene` (sky and ground). There is no gameplay yet.
- **Nothing from this work is committed.** The only commit is `c3dfd99 first commit`. Section 4 lists what is

## 3. How to build and verify

Run from the repo root. Unity must **not** have the project open (one Unity instance per project).

```bash
UNITY=~/Unity/Hub/Editor/6000.6.9f1/Editor/Unity
LOG=sample-game/Logs/build.log      # Logs/ is gitignored. Do not use /tmp (see section 6).

# Android APK -> sample-game/Builds/Android/NimbusSample.apk
$UNITY -batchmode -nographics -quit -projectPath sample-game -buildTarget Android \
  -logFile $LOG -executeMethod Nimbus.Build.BuildRunner.BuildAndroid

# WebGL -> sample-game/Builds/WebGL/   (add -development for a faster, unoptimised build)
$UNITY -batchmode -nographics -quit -projectPath sample-game -buildTarget WebGL \
  -logFile $LOG -executeMethod Nimbus.Build.BuildRunner.BuildWebGL -development

# Serve the WebGL build on the LAN (port 8080, binds 0.0.0.0)
tools/serve-webgl.sh
```

`BuildRunner` flags: `-buildAab` (Android App Bundle), `-development`, `-outputPath <dir>`. Release signing is read from
`NIMBUS_KEYSTORE_PATH`, `NIMBUS_KEYSTORE_PASS`, `NIMBUS_KEY_ALIAS`, `NIMBUS_KEY_PASS`. With none set, Android builds are
signed with Unity's debug keystore.

Typical timings: Android cold 9.8 min, warm 4.3 min. WebGL about 2 min.

**How to tell a build really worked.** Do not trust the process exit status alone (see issue 13). Check all of:

1. The log contains `[BuildRunner] Succeeded: ...` (a failure prints `[BuildRunner] Build Failed`).
2. The output exists (`Builds/Android/NimbusSample.apk`, or `Builds/WebGL/index.html`).
3. For the APK, inspect it:
   ```bash
   T=~/Unity/Hub/Editor/6000.6.9f1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/build-tools/36.0.0
   $T/aapt dump badging sample-game/Builds/Android/NimbusSample.apk | grep -E "^package|sdkVersion|native-code"
   $T/apksigner verify --print-certs sample-game/Builds/Android/NimbusSample.apk
   ```
4. For WebGL, smoke test in headless Chrome against the running server and read the console and screenshot:
   ```bash
   google-chrome --headless=new --no-sandbox --user-data-dir=/tmp/chrome-smoke \
     --enable-unsafe-swiftshader --use-angle=swiftshader --ignore-gpu-blocklist \
     --window-size=420,800 --virtual-time-budget=25000 --enable-logging=stderr --v=0 \
     --screenshot=/tmp/chrome-smoke/shot.png http://localhost:8080/ 2> /tmp/chrome-smoke/chrome.log
   ```

Lint and manifest checks (same as CI):

```bash
dotnet format whitespace --folder . --verify-no-changes --include packages/ sample-game/Assets/_Project/
python3 tools/ci/validate_manifests.py
```

## 4. What was changed

**New files**

- `sample-game/Assets/_Project/Editor/BuildRunner.cs` (plus Unity-generated `.meta` files). Headless entry points
  `BuildAndroid`, `BuildiOS`, `BuildWebGL`. Output defaults to `<project>/Builds`, not the process working directory.
  `BuildWebGL` forces WebGL compression to Disabled so any static server can host the output.
- `tools/serve-webgl.sh`: serves `sample-game/Builds/WebGL` with `python3 -m http.server`. It binds all interfaces, so
  stop it when you are done.
- `docs/HANDOFF.md` (this file).

**Edited on purpose**

- `.github/workflows/ci.yml`: Unity version `6000.3.8f1` to `6000.6.9f1` (both jobs); removed the "Setup BuildRunner"
  copy step (it copied from a `tools/build/` folder that never existed); replaced the crashing `dotnet format` command
  with folder mode.
- `.gitignore`: added `sample-game/build/`, `sample-game/Data/`, `sample-game/.utmp/` (leftovers from Unity, Burst and
  Gradle).
- `README.md`: new "Building" section.
- `packages/com.nimbus.haptics/Runtime/HapticsService.cs`: the `#else` fallback is now `#elif !UNITY_WEBGL` (see issue 11).
- 10 package `.cs` files: whitespace-only fixes from `dotnet format` (audio x3, config, core, input, save, scene x2, ui).
- `sample-game/Packages/manifest.json`: removed `com.unity.ai.inference`. `packages-lock.json` was regenerated by Unity
  (the `ai.inference` and `dt.app-ui` entries are gone).
- `sample-game/ProjectSettings/ProjectSettings.asset`: company, product name and application IDs (Android, Standalone,
  iPhone, tvOS) changed from the Unity template defaults.

**Changed by Unity as a side effect of building (not hand-edited)**

- `ProjectSettings.asset`: `webGLCompressionFormat` changed from `0` (Brotli) to `2` (Disabled) because `BuildWebGL` sets
  it. **Reset it to Brotli or Gzip before a production WebGL release.** Unity also added a `SENTIS_ANALYTICS_ENABLED`
  define for Android and WebGL; it is a leftover from the removed package and harmless. It also added the Input System
  actions asset to `preloadedAssets`.
- `Assets/Settings/Mobile_RPAsset.asset`, `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset`,
  `ProjectSettings/GraphicsSettings.asset`: URP shader-prefilter and graphics bookkeeping that Unity rewrites on build.

**New untracked files generated by AppLovin and the External Dependency Manager (decide whether to commit)**

- `Assets/MaxSdk/Resources/AppLovinSettings.asset` (the `sdkKey` is empty).
- `Assets/Plugins/Android/{mainTemplate.gradle, settingsTemplate.gradle, gradleTemplate.properties}`.
- `ProjectSettings/AndroidResolverDependencies.xml` (lists `com.applovin:applovin-sdk:13.6.2`).
- `ProjectSettings/AppLovinInternalSettings.json`.

None of these contain secrets (checked).

## 6. Gotchas for the next agent

- **One Unity instance per project.** A batchmode build fails if the Editor has `sample-game` open.
- **Do not edit `packages/`, `Assets/` or `ProjectSettings/` while a Unity build is running.** It triggers a recompile in
  the middle of the build. Wait for it to finish.
- **Unity rewrites `ProjectSettings` files during builds**, and settings changed through the `PlayerSettings` API inside a
  build method are persisted. Re-read a file before editing it, and review `git diff` after every build.
- **Re-adding `com.unity.ai.inference`, or any package that depends on `com.unity.dt.app-ui`, will probably break
  WebGL again** (issue 12). `com.unity.ai.assistant` is still in the manifest. It does not depend on AppUI.
- **Platform switches reimport assets.** `Library/` is large (about 2.7 GB and growing) and the disk is nearly full.
- **Code style is enforced:** file-scoped namespaces, Allman braces, `_camelCase` private fields. `sample-game/Assets/csc.rsp`
  enables `-langversion:latest -nullable:enable` (file-scoped namespaces need C# 10 or later).
- **`.remember/` notes are auto-generated and contain mistakes.** One says `com.unity.ai.assistant` was removed. It was
  not; only `com.unity.ai.inference` was.
- **`tools/serve-webgl.sh` listens on all interfaces.** Stop it when you are finished.

## 7. What was verified, and how

- **Android APK** (34 MB; 43 MB before removing AppUI): `aapt` shows package `com.nimbus.samplegame`, min SDK 26, target
  SDK 36, `native-code: arm64-v8a`. `apksigner` confirms it is signed with the Android Debug certificate. `lib/arm64-v8a`
  contains `libil2cpp.so`.
- **WebGL** (93 MB uncompressed development build): `index.html`, loader, framework, data and wasm all returned HTTP 200
  with correct content types (`application/wasm` for the wasm). Headless Chrome booted the Unity player and rendered the
  scene, with no errors in the console. The only warnings were the browser's "AudioContext must be resumed after a user
  gesture" notices.
- Format check and manifest validation pass locally.

**Not verified:** installing or launching the APK on a device or emulator; WebGL on a phone browser (the default Unity
template may not be responsive); CI in any form; `-buildAab`; release signing; the iOS export.
